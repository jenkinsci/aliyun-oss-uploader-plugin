# Aliyun OSS Uploader 2.1.0 release notes

English | [简体中文](2.1.0.zh-CN.md)

Release date: November 16, 2026.

2.1.0 lowers the minimum Jenkins version from 2.555.3 to **2.479.3** and the minimum Java version from 21 to **17**, making the object ACL options, missing-path handling, and Pipeline fixes from 2.0.0 available to more installations.

## Requirements

- Jenkins **2.479.3 or newer**.
- **Java 17 or Java 21** on that baseline. Newer Jenkins releases may require a newer Java runtime. Both the controller and agents must meet the requirements of the Jenkins version in use.
- Source builds require Maven **3.9.6 or newer** and JDK 17/21. The Maven Wrapper uses 3.9.9.

The published 2.0.0 package still requires Jenkins 2.555.3 and Java 21. The lower requirements take effect in 2.1.0.

## Compatibility changes

- Use a BOM matching the Jenkins 2.479 baseline, with compatible Pipeline test dependencies and Gson API versions.
- Retain the existing Structs and Commons Lang API versions, which support Jenkins 2.479.3.
- Declare Bouncy Castle API as a runtime plugin dependency for the Aliyun SDK's cryptography library and update the strict HPI packaging inventory accordingly.
- Compile for Java 17 and run CI with Java 17 and Java 21.

The upload implementation and Aliyun OSS SDK 3.18.5 are unchanged. Existing job XML, `aliyunOSSUpload` parameters, object ACL settings, and missing-path options remain compatible. Existing Pipelines do not need to be rewritten.

## Upgrade and validation

Install 2.1.0 and its dependencies through the Jenkins plugin manager. Manual HPI installations also require compatible dependency plugins. Installations using 1.x on Jenkins older than 2.479.3 must first upgrade Jenkins and Java.

On Jenkins 2.479.3, Java 17 and Java 21 each passed 21 automated tests, static analysis, and HPI packaging checks. Tests cover legacy configuration, Pipeline execution, file and directory uploads, ACL request headers, and missing-path behavior. Live OSS smoke tests were not repeated for this release.
